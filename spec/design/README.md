# `design/` —— 跨端设计 token

`tokens.json` 收录**已经在某个端落地**的取值，并注明来源文件。它不是设计稿，也不许先设计再回填：
新取值先进某端的代码（或 `Themes/*.xaml` 这类资源文件），确认效果后再回来记一笔。

## 为什么这么严

三端不共享实现，只共享「答案」。颜色、字号这种最容易被各自随手定的东西，一旦分散就没有收敛点——
同一个「次要文字」在 Windows 是 `#A7B0BC`、Linux 是 `#9AA4B0`、Android 是 `#8E98A4`，
用户看着是三个应用。token 就是那个收敛点。

## 收录口径

| 收录 | 不收录 |
|---|---|
| 已落地的颜色（含深 / 浅 / 高对比三档） | 只在设计稿里出现的颜色 |
| 语义层级（背景 / 表面 / 表面次层 / 边框 / 三级文字） | 单个组件的一次性色值 |
| 圆角与边框这类语言级约定 | 某个页面的临时测量值 |
| 字号（页面标题 / 分区标题 / 正文 / 说明 / 数字） | 某一个控件模板里的字号 |
| 布局不变量（卡片内边距、边框宽度） | 具体页面的边距 |

## 现在的状态

- **只有 Windows 端落地**（`windows/src/PezMax.App/Themes/PezMax.xaml`），所以 `sources` 只有一条。
- 圆角全是 0（Kanesumi Design 的直角约定），所以 `radius` 是一组 0 —— 这不是「还没定」，
  是「定成了直角」。
- **动画 token 一个都没有**：三端都还没写动效。按铁律，动画曲线只能来自 Sokuou 及其扇区分支，
  等某一端真正落地第一处动画时再回填 `motion` 段，不要提前编。
- 强调色不写死：Windows 跟随系统强调色，读不到回落钴蓝 `#3B82F6`（`ARCHITECTURE.md` D11）。

## Linux / Android 接入时

两端各自的取值来源是它们自己的代码（`linux/` 的主题模块、`android/` 的 Compose 主题）。
落地后把**与 Windows 不同的部分**标出来，并说明为什么不同——「各端不逐像素对齐」，
但差异必须是**选择**，不是**疏忽**。
